------------------------------------------------------------------
0. PROPÓSITO DE ESTE DOCUMENTO
------------------------------------------------------------------
Este archivo es la fuente de verdad del proyecto "La Arboleda". Reúne
la visión creativa, el contexto académico real (sílabo del curso),
el inventario de recursos disponibles, la arquitectura técnica y una
hoja de ruta fase por fase alineada al cronograma del curso.

No contiene código. Contiene decisiones y especificaciones para que
tanto el equipo humano como un agente de programación (por ejemplo
opencode) puedan implementar el proyecto de forma consistente, sin
adelantarse a contenidos que el curso todavía no cubre y sin perder
de vista el objetivo emocional del proyecto: transmitir la calma y
la belleza del campo mediante una experiencia web con sensación de
profundidad/dimensión, lograda solo con HTML, CSS y JS vainilla
(más lo que el curso vaya incorporando: SASS/LESS, animaciones,
frameworks CSS).

Regla de oro para cualquier persona o agente que trabaje sobre este
plan: NO implementar técnicas de una unidad futura del curso en una
entrega que corresponde a una unidad anterior, salvo que se indique
explícitamente como "extra permitido" en este documento. El objetivo
es un proyecto vistoso, pero defendible académicamente semana a
semana.


------------------------------------------------------------------
1. VISIÓN DEL PROYECTO
------------------------------------------------------------------
Nombre: La Arboleda
Formato: sitio web estático de una sola página (scrollytelling),
  HTML + CSS + JS vainilla, sin frameworks de JS.
Idea central: el usuario no "lee" una página informativa, la
  "recorre". El scroll simula una caminata por el campo: se abre en
  un paisaje amplio, avanza por la vegetación, se acerca al detalle
  de las flores, y cierra en el cielo/la calma. Cada bloque
  informativo que exige el curso (encabezado, hero, 2-3 bloques de
  contenido, evidencia responsive, footer) se narra como un
  "capítulo" de ese recorrido en vez de como secciones sueltas.
Supuesto académico declarado (para cumplir el requisito de
  "problema o necesidad"): "La Arboleda" se presenta como un
  proyecto conceptual/experiencial que responde a la necesidad de
  espacios digitales de pausa frente a la sobreestimulación de
  pantallas, usando fotografía propia del campo como material
  central. Se declara explícitamente como supuesto académico, no
  como servicio real, cumpliendo lo permitido en la guía del
  proyecto integrador ("simulado si se declara como supuesto
  académico").
Tono visual: cálido, orgánico, pausado. Paleta extraída de las
  fotos propias (verdes musgo, terracota/naranja de flores, crema,
  azul cielo apagado). Tipografía serif cálida para títulos + sans
  limpia para cuerpo. Nada de estética "landing corporativa".

    no solo Flexbox.

    transiciones, transformaciones 2D/3D) están formalmente
    cubiertas recién en la Unidad 3 (semanas 9-12). Todo lo que se
    use antes de eso debe limitarse a transiciones/animaciones muy
    básicas o quedar documentado como "adelanto justificado" — ver
    sección 6.

    en la Unidad 2. El plan de arquitectura de archivos (sección 5)
    ya se diseña pensando en esa migración para que no implique
    reescribir todo desde cero.
  - La Unidad 4 exige demostrar el uso de un framework CSS. Se
    recomienda Tailwind CSS (ver sección 8.4) porque permite
    mantener el diseño de autor sin heredar la estética visual por
    defecto de Bootstrap/Materialize/Material Design.

4. ESTRUCTURA NARRATIVA / MAPA DEL SITIO
------------------------------------------------------------------
Una sola página, scroll vertical, dividida en "capítulos". Cada
capítulo cumple una función narrativa Y un requisito del rubric del
curso al mismo tiempo (columna derecha).

CAP. 0 — Portal de entrada (header + hero)
  Narrativa: pantalla de bienvenida, paisaje abierto de fondo (img10
    o img20), título "La Arboleda", frase breve que transmite la
    promesa emocional del proyecto. Video1.mp4 en loop muy sutil
    como textura (opcional, evaluar peso/rendimiento).
  Rubric: encabezado con título y descripción clara + navegación de
    3 enlaces internos (ver nombres de anclas abajo).

CAP. 1 — "El camino" (ancla: #camino)
  Narrativa: transición hacia la vegetación densa, primer bloque de
    contenido — presenta el "supuesto académico" (la necesidad que
    atiende el proyecto) de forma poética, no como texto de negocio.
  Rubric: sección "Problema o necesidad".

CAP. 2 — "El detalle" (ancla: #detalle)
  Narrativa: acercamiento a las macro de flores (img1, img5 y
    similares). Aquí va el contenido principal: 2-3 bloques
    informativos que explican la propuesta del proyecto (qué es "La
    Arboleda", qué técnicas visuales usa, por qué fotografía propia).
  Rubric: sección "Contenido principal" (2-3 componentes
    informativos).

CAP. 3 — "El cielo" / cierre reflexivo (ancla: #cielo)
  Narrativa: vuelta al plano abierto, cierre emocional del
    recorrido.
  Rubric: puede fusionarse con el cierre de "Contenido principal" o
    quedar como bloque adicional de cierre narrativo (no obligatorio
    por rubric, pero recomendado para redondear la experiencia).

CAP. 4 — Evidencia responsive (ancla interna, no necesariamente en
  el nav)
  Contenido: registro de las pruebas en 375px, 768px y 1440px, y una
  explicación breve de al menos una corrección/decisión tomada.
  Rubric: sección "Evidencia de revisión responsive" (obligatoria,
  la pide explícitamente la guía de la Semana 1).

FOOTER
  Créditos del proyecto, integrantes del equipo, curso, versión.

NAV (3 enlaces obligatorios): usar los nombres poéticos de los
  capítulos como texto visible, pero anclados a IDs semánticos
  claros para no perder trazabilidad con el rubric:
    <a href="#camino">El camino</a>
    <a href="#detalle">El detalle</a>
    <a href="#cielo">El cielo</a>

6. TOOLKIT TÉCNICO PARA LA SENSACIÓN "DIMENSIONAL"
   (qué técnica, cuándo está permitida usarla, y por qué)
------------------------------------------------------------------
6.1 Grid layout para el mosaico de detalle (PERMITIDO desde semana 3)
    Usar CSS Grid para el bloque "El detalle": una composición
    asimétrica (no una grilla uniforme tipo catálogo) combinando
    imágenes grandes y pequeñas con grid-template-areas, para que
    el mosaico de flores se sienta compuesto a mano y no "generado".

6.2 Ken Burns sutil sobre imágenes de fondo (@keyframes con scale +
    translate lentos, 20-30s)
    Formalmente es contenido de la Unidad 3 (animaciones). Se puede
    adelantar una versión MÍNIMA (una sola animación, muy simple,
    en el hero solamente) como "extra permitido" siempre que se
    documente en el README como una decisión de diseño consciente y
    no se generalice a toda la página antes de la Unidad 3. Evitar
    abusar de esto antes de semana 9.

6.3 Parallax por capas (transform: translateY controlado por scroll)
    Requiere transform + transiciones -> formalmente Unidad 3. NO
    implementar antes de semana 9 salvo lo indicado en 6.2. Se
    activa como fase completa a partir de la Unidad 3 (ver hoja de
    ruta, sección 7).

6.4 Perspectiva 3D (perspective + transform-style: preserve-3d)
    Igual que el parallax, corresponde a la Unidad 3. Reservar para
    la fase de animaciones.

6.5 Scroll-snap por capítulos (scroll-snap-type / scroll-snap-align)
    Es CSS de layout/scroll, no depende de animaciones. Se puede
    introducir desde la Unidad 1 si se desea, pero evaluar si suma
    o resta a la narrativa (un scroll libre también funciona bien
    para "recorrido"). Decisión de equipo, no bloqueante.

6.6 Variables CSS / custom properties para la paleta
    Disponible desde el día uno, es CSS estándar, no pertenece a
    ninguna unidad específica. Implementar desde la primera entrega
    en css/base.css. Esto además prepara el terreno para la
    migración a variables de SASS/LESS en la Unidad 2 (mapeo directo
    de custom properties a variables del preprocesador).

6.7 Textura de grano / viñeta orgánica
    Un pseudo-elemento con mix-blend-mode o una imagen de ruido en
    baja opacidad. CSS estándar, sin dependencia de unidad. Se puede
    incluir desde la primera entrega si el equipo lo considera
    necesario para el "look" general, pero es un detalle menor —
    priorizar layout y contenido primero.

6.8 IntersectionObserver + reveal al hacer scroll (única pieza de
    JS "seria")
    No es contenido del curso de CSS, es JavaScript vainilla básico.
    Se puede introducir en cualquier momento sin conflicto con el
    sílabo, ya que el curso no restringe el uso de JS, solo evalúa
    CSS. Se recomienda incorporarlo recién cuando exista contenido
    real que revelar (a partir de que el Capítulo 2 esté armado),
    para no invertir tiempo en algo sin sustancia que animar.

6.9 prefers-reduced-motion
    Obligatorio implementar en cuanto exista CUALQUIER animación o
    parallax (a partir de 6.2 o 6.3). No es opcional.

      dentro de scss/, con partials (_variables.scss, _base.scss,
      _layout.scss) y un main.scss que compile a css/styles.css.
    - Aprovechar el anidamiento de SASS/LESS para expresar mejor la
      relación entre capítulos/secciones (ej. .capitulo { &__titulo
      {...} &__imagen {...} }).
    - No introducir aún animaciones/transiciones nuevas — el foco de
      esta fase es la migración técnica, no lo visual.
  Entregable de PC2: el sitio de la Fase 1, ahora construido y
    documentado sobre SASS y/o LESS.

FASE 3 — Semanas 9 a 12 (rumbo a PC3, 30% — la de mayor peso hasta
  ese punto)
  Objetivo: aquí se activa todo el toolkit de "profundidad" — esta
  es la fase donde el proyecto pasa de "bonito" a "no he visto algo
  similar".
  Tareas:
    - Semana 9: implementar animaciones CSS (@keyframes) en:
      Ken Burns generalizado a más imágenes de fondo, aparición
      progresiva de texto (fade + translateY) en cada capítulo.
    - Semana 10: implementar transiciones y transformaciones:
      parallax por capas (6.3) con transform: translateY controlado
      por scroll vía js/main.js; perspectiva 3D (6.4) en al menos el
      Capítulo 2 (detalle) para dar sensación de capas flotantes
      (fondo/vegetación/flor).
    - Semana 11: pruebas de compatibilidad entre navegadores
      (Chrome, Firefox, Safari si es posible, Edge) — documentar en
      el README cualquier prefijo o fallback necesario.
    - Implementar obligatoriamente prefers-reduced-motion (6.9) en
      cuanto se agregue la primera animación de esta fase.
    - Optimizar performance: loading="lazy" en imágenes fuera del
      viewport inicial, revisar peso total de la página.
  Entregable de PC3: versión con profundidad/parallax/animaciones
    completa y con compatibilidad cross-browser verificada.

FASE 4 — Semanas 13 a 18 (rumbo al examen final, 30%)
  Objetivo: incorporar un framework CSS sin perder la identidad
  visual ya construida.
  Tareas:
    - Semana 13-14: si el docente pide demostrar Bootstrap
      específicamente, usarlo de forma acotada (ej. solo para el
      sistema de grid de una sección secundaria o componentes de
      formulario si se agrega alguno), evitando que sobrescriba la
      estética general con sus estilos por defecto.
    - Semana 15: RECOMENDADO — usar Tailwind CSS como framework
      principal a demostrar, aplicándolo en una sección nueva o en
      un refactor parcial, porque al ser utility-first no impone
      una identidad visual propia y es compatible con el diseño ya
      construido en SASS/LESS.
    - Semana 16-17: si se pide comparar con Material Design /
      Materialize, puede resolverse como un anexo comparativo
      (documento o sección de "making of") en vez de reescribir todo
      el sitio con esos frameworks, salvo que el docente exija
      implementación real — confirmar con el profesor.
    - Semana 18: pulido final, revisión de accesibilidad completa,
      preparación de la sustentación (ver sección 9).
  Entregable final: versión pulida y con framework CSS integrado de
    forma justificada, lista para examen final.

8. LINEAMIENTOS DE CONTENIDO Y DISEÑO
------------------------------------------------------------------
8.1 Tono de voz de los textos
  Frases cortas, en primera persona o segunda persona cercana ("tú"),
  evitar lenguaje corporativo/comercial. Priorizar sensaciones sobre
  descripciones técnicas ("el aire se siente distinto aquí" en vez
  de "descubre nuestra propuesta de valor").

8.2 Paleta de color — VALORES REALES, extraídos de las fotos
  (análisis de color dominante/más saturado sobre img1, img4, img5,
  img17, img9, img10, img21, img22 y el follaje de fondo). Estos
  valores ya se pueden usar como variables CSS definitivas desde la
  Fase 1; solo verificarlos visualmente una vez montado el layout
  por si algún contraste necesita ajuste fino:

    --color-verde-musgo-oscuro: #232C18;   /* fondo oscuro, follaje
                                               denso (base de img3,
                                               img14) */
    --color-verde-musgo:        #4B5A32;   /* verde medio, texto
                                               sobre fondos claros,
                                               acentos de vegetación */
    --color-verde-suave:        #7C8F52;   /* verde claro, detalles
                                               secundarios */
    --color-terracota:          #C9793A;   /* naranja cálido de las
                                               flores de img1/img2 */
    --color-rojo-flor:          #C4432A;   /* rojo-anaranjado de las
                                               flores tubulares de
                                               img5 */
    --color-morado-flor:        #8B2FA0;   /* morado vivo de las
                                               flores de img4/img7 */
    --color-amarillo-flor:      #E4C750;   /* amarillo cálido de
                                               img17, uso en acentos
                                               pequeños, no en
                                               grandes superficies */
    --color-azul-cielo:         #6D93D6;   /* azul de las fotos de
                                               cielo (img9, img10) */
    --color-dorado-campo:       #A67C3D;   /* dorado del trigal/
                                               ladera (img21, img22),
                                               usar en la sección
                                               Cap.3 "El cielo" */
    --color-crema:              #F6F1E4;   /* fondo claro cálido,
                                               NO blanco puro, para
                                               mantener la atmósfera
                                               orgánica */
    --color-texto-oscuro:       #24291B;   /* texto principal sobre
                                               fondos claros, tono
                                               casi negro con matiz
                                               verde para cohesión */
    --color-texto-claro:        #F6F1E4;   /* texto sobre fondos
                                               oscuros (hero, Cap.1) */

  Uso recomendado: verde-musgo-oscuro y crema como los dos fondos
  base del sitio (alternar por capítulo); terracota, rojo-flor y
  morado-flor como acentos puntuales (títulos de capítulo, hover de
  enlaces, bordes); dorado-campo reservado casi exclusivamente para
  el Cap.3 "El cielo" para que ese cierre se sienta distinto y
  luminoso frente al resto del recorrido, más verde y umbrío.
  Evitar usar más de 2-3 colores de acento por pantalla a la vez
  para no perder la sensación de calma.

8.3 Tipografía
  Títulos: fuente serif cálida (ej. Fraunces, Playfair Display o
    similar disponible en Google Fonts).
  Cuerpo: fuente sans limpia (ej. Inter, Work Sans, o similar).
  Jerarquía generosa: line-height amplio, tracking normal en cuerpo,
  tamaños grandes en hero (usar clamp() para fluidez, ya usado en la
  plantilla base).

8.4 Framework recomendado para la Fase 4
  Tailwind CSS, por ser utility-first y no imponer estética visual
  propia — permite seguir viéndose como "La Arboleda" y no como una
  plantilla genérica de framework. Confirmar con el docente si exige
  usar específicamente Bootstrap/Materialize/Material Design en
  algún entregable puntual antes de descartarlos.
